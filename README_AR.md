# IR Mobile Store — منصة استرجاع معلومات الهواتف والتجارة الإلكترونية

[English](README.md) | [العربية](README_AR.md)

> منصة تجمع بين استرجاع معلومات الهواتف، جمع البيانات من الويب، المعالجة المسبقة، المقارنة بين أكثر من مصدر، وطبقة تجارة إلكترونية مبنية باستخدام Laravel.

## نظرة عامة

IR Mobile Store هو مشروع يجمع بين **Information Retrieval، جمع البيانات، ومعالجة البيانات، والتجارة الإلكترونية** في مجال الهواتف المحمولة.

المستودع يحتوي على طبقتين رئيسيتين:

1. مساحة عمل Python/Scrapy لجمع بيانات الهواتف من مصادر مختلفة ومعالجتها وتحويلها إلى بيانات منظمة؛
2. تطبيق Laravel داخل [`e-store/`](e-store/) يوفر واجهات Web وAPI للمنتجات، الشركات، التصنيفات، البحث، المقارنة، السلة، الطلبات، العروض، الكوبونات، المستخدمين، التقييمات، الدفع والإدارة.

المشروع لا يقتصر على عرض المنتجات فقط؛ بل يوضح دورة كاملة تبدأ من جمع البيانات الخارجية، مروراً بالمعالجة والتخزين، وصولاً إلى عرضها واستخدامها داخل واجهات البحث والاسترجاع والتجارة الإلكترونية.

## استرجاع المعلومات

يحتوي النظام على Endpoint خاص باسترجاع بيانات نفس الهاتف من مجموعتي بيانات مختلفتين، ثم يعيد النتائج المتوفرة من المصدرين معاً.

هذا يسمح بعرض أو مقارنة معلومات الهاتف من أكثر من مصدر بدلاً من الاعتماد على كتالوج واحد فقط.

توجد نماذج بيانات منفصلة داخل Laravel لمصادر مختلفة مثل `Gsm` و`Mobolist`، وتشمل خصائص مثل الشاشة، المعالج، GPU، الكاميرا، التخزين، الحساسات، الاتصال، الوزن وغيرها من مواصفات الجهاز.

## جمع البيانات والمعالجة المسبقة

المجلد [`crawl_scrap_preproccing/`](crawl_scrap_preproccing/) يمثل الجزء الخاص بجمع البيانات ومعالجتها.

ويتضمن:

- Crawling وScraping باستخدام Python؛
- مشروع Scrapy؛
- استخراج تفاصيل المنتجات؛
- Crawlers لعدة أنواع وعلامات من الهواتف؛
- ملفات CSV وJSON منظمة؛
- مراحل preprocessing؛
- استخراج نصوص المواصفات؛
- قوائم روابط المصادر؛
- تجارب لاستخراج المواصفات وتحويل النص إلى بيانات منظمة.

كود الـscraping يقوم باستخراج تفاصيل صفحات الهواتف وتحويلها إلى سجلات منظمة يمكن لاحقاً معالجتها وإدخالها في طبقة التطبيق.

## طبقة الـAPI

الـAPI مبنية باستخدام Laravel وتحتوي على Resource-style endpoints بالإضافة إلى عمليات خاصة بسير العمل التجاري.

من أهم المجالات المتوفرة:

- المنتجات والتصنيفات؛
- العلاقات بين الشركات والمنتجات؛
- أحدث المنتجات؛
- استرجاع معلومات الهاتف من أكثر من مصدر؛
- البحث؛
- إدارة المستخدم والعناوين؛
- إنشاء الطلبات واسترجاعها؛
- التقييمات؛
- الخصومات والعروض؛
- رسائل التواصل؛
- بيانات الدفع.

العمليات الحساسة تستخدم Laravel Sanctum في التنفيذ الحالي.

## تطبيق الويب

طبقة الويب تحتوي على Routing متعدد اللغات وتدفقات مستخدمين مسجلين تشمل:

- تفاصيل المنتجات؛
- تصفح الشركات والتصنيفات؛
- إدارة السلة؛
- البحث والفلاتر؛
- تقييم المنتجات؛
- الملف الشخصي؛
- سجل الطلبات؛
- مسارات مرتبطة بالـcheckout؛
- إدارة المنتجات والشركات والتصنيفات من لوحة الإدارة.

كما يحتوي المشروع على دعم localization وأدوات Vue ضمن frontend asset pipeline.

## التشغيل المحلي

لتطبيق Laravel:

```bash
cd e-store
composer install
npm install
npm run dev
```

ويحتاج المشروع أيضاً إلى إعداد Laravel المعتاد مثل `.env` وApplication Key وقاعدة البيانات والـmigrations.

لإنشاء build للإنتاج:

```bash
npm run build
```

أما جزء الـcrawling فهو بيئة Python منفصلة وله dependencies خاصة به.

## ملاحظات هندسية

المستودع يعرض عدة مراحل ضمن نفس دورة النظام:

جمع البيانات → استخراجها → معالجتها → تخزينها بشكل منظم → استرجاعها عبر API → استخدامها ضمن واجهة Web وتجارية.

لذلك أفضل توصيف للمشروع هو **منصة استرجاع معلومات الهواتف والتجارة الإلكترونية** وليس مجرد متجر هواتف.

## حالة التشغيل والأمان

يوجد PHPUnit وأدوات اختبار داخل المشروع، لكن هذا التحديث التوثيقي لا يدعي أن جميع الاختبارات أو الـmigrations أو الـcrawlers أو المصادقة أو الدفع تم التحقق منها حالياً بشكل كامل.

حزم Stripe وLaravel Cashier موجودة في المشروع، لكن Payment API الحالي يقوم أساساً بتسجيل بيانات الدفع، بينما كود Stripe PaymentIntent موجود بشكل معلق داخل الـcontroller. لذلك لا يجب وصف المشروع على أنه يملك تكامل Stripe مؤتمت ومثبت بشكل كامل قبل إجراء Audit تشغيلي وأمني منفصل.

كذلك مواقع ومصادر الـscraping قد تتغير مع الوقت، لذلك يجب إعادة التحقق من الـcrawlers قبل استخدامها بشكل متكرر أو في بيئة إنتاج.

## تموضع المشروع

المشروع يوضح Pipeline هندسي متكامل:

`Web Sources → Crawling → Extraction → Preprocessing → Structured Mobile Data → Laravel Models → Search / Retrieval APIs → Web & Commerce Workflows`

وهو يجمع بين Backend Development، API Design، Data Modeling، Web Scraping، Information Retrieval ومفاهيم E-commerce داخل مستودع واحد.
